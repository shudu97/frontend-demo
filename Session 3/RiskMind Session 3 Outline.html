Plugin Introduction

Static infographic

Static infographic with a short zoom-in. Open with the concentric diagram: all four layers drawn, only the outermost layer (Plugin) highlighted and the three inner layers grayed. Then zoom into a folder tree, and the arrows from each skill to the reference files appear one by one.

Official definitions (verbatim, with sources)
  • Plugin: “A Claude Code plugin is a directory of skills, agents, hooks, MCP servers, or other components that Claude Code installs and loads as one unit.” Claude Code plugins overview
  • When to use one: “Use a plugin when you want several skills, subagents, hooks, or MCP servers packaged as one unit.” Claude Code plugins overview
  • In the Agent SDK: “Package skills, agents, hooks, and MCP servers, and load them by local path” Agent SDK overview
Bullets
  • Why we introduce plugins: RiskMind is an Agent + Plugin system. Risk Managers work mainly on the plugin side, and all business context reaches the agent through plugins.
  • What is in a RiskMind plugin
    • One plugin per product (for example, FX Option)
    • One skill per metric inside it (today Stress P&L; VaR and Sensitivities are possible next)
    • MCP configuration for the data sources that product needs
    • Shared knowledge does not sit inside a plugin. It sits in the parent folder of the plugins and is shared by all of them.
  • Plugin and agent are decoupled (a short reminder; the full message is on the Why Agent + Plugin slide)
    • The agent only needs to be pointed at the plugin folder
    • Adding or changing a plugin does not touch the agent, so a Local Risk Manager only needs to know how a plugin works
  • Why a plugin and not standalone skills
    • Distribution: all metrics of a product ship together as one unit
    • One picture: business knowledge (skills) and data access (MCP) live in the same unit
    • Write once, refer many: the shared reference folder in the parent folder of the plugins holds what all products share, such as the enterprise scenario descriptions, the shock definitions, and the top-down analysis process. It is maintained in one place, and each skill says when to refer to which file.

Skill IntroductionComponents

Static infographic

Built up piece by piece. Start with the skill as a folder, then each component appears in turn: SKILL.md (meta, then detail), scripts, references. The last frame shows the arrows from SKILL.md to scripts and references.

Official definitions (verbatim, with sources)
  • Agent Skills: “organized folders of instructions, scripts, and resources that agents can discover and load dynamically to perform better at specific tasks” Anthropic Engineering, Equipping agents for the real world with Agent Skills
  • Bundled files: “skills can bundle additional files within the skill directory and reference them by name from SKILL.md. These additional linked files are the third level (and beyond) of detail, which Claude can choose to navigate and discover only as needed.” Anthropic Engineering, Equipping agents for the real world with Agent Skills
  • Code: “Skills can also include code for Claude to execute as tools at its discretion.” Anthropic Engineering, Equipping agents for the real world with Agent Skills
Bullets
  • What a skill is
    • In RiskMind, one skill is one metric's analysis for one product
    • The Risk Manager writes the whole skill: the analysis process in natural language (SKILL.md), the scripts, and any references
  • SKILL.md, in two layers
    • Meta: name and description. It tells the agent what the skill is and when to use it.
    • Detail: the body of the file. It describes the analyses (Portfolio Analysis, Drill Down, Ad-hoc), defines the slash command and its parameters, and says which references to read and which scripts to run.
    • Each skill writes only what is specific to its own metric; shared knowledge lives in references
  • scripts
    • Python code that does the exact work (data processing, visualization); it lives inside the skill and is written by the Risk Manager as part of the skill
    • Each script is written as a CLI: it has a command-line entry point, takes parameters (for example the file location from the previous step), and writes its output
    • The agent runs it with Bash, so SKILL.md states the command and its parameters
  • references
    • Knowledge files the agent reads only when needed
    • Two places: the skill's own folder (specific to one metric, optional) and the shared reference folder in the parent folder of the plugins (shared across all products)
    • SKILL.md states when to read which file and where it is
  • SKILL.md is the entry point: scripts and references are used because SKILL.md mentions them
